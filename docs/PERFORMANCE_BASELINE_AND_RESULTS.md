# รายงานผลการวัดประสิทธิภาพและเกณฑ์มาตรฐาน (Performance Baseline & Empirical Benchmark Report)
**ระบบ:** HRT School Inventory Management System  
**สถานศึกษา:** โรงเรียนหรเทพ(รุ่งเรืองประชาสามัคคี) สังกัดองค์การบริหารส่วนจังหวัดสระบุรี  
**รุ่นเป้าหมาย:** `v2.7.0-rc.1` (อ้างอิงข้อมูลจาก `v2.7.0-dev.5` / `scripts/benchmark_engine.js`)  
**วันเวลาที่ทำการวัด:** 25 ตุลาคม 2569  
**เครื่องมือทดสอบ:** Node.js Benchmark Runner (30 iterations per tier, statistical variance, p95 analysis)

---

## 1. บทสรุปผู้บริหารด้านประสิทธิภาพ (Executive Summary)

จากการทดสอบเชิงประจักษ์ (Empirical Performance Benchmark) บนชุดข้อมูลจำลองตามขนาดจริงของโรงเรียนขนาดกลาง-ใหญ่ โดยเปรียบเทียบระหว่างสถาปัตยกรรมเดิม (Unscoped Full-Table Payload) และสถาปัตยกรรมปรับปรุงใหม่ในรุ่น `v2.7.0` (Scoped Keys, Scoped History Slicing, Data Revision Token, Dynamic Caching):

1. **การลดขนาด Payload ข้อมูลประวัติการเคลื่อนไหว (History Payload Reduction):**
   - ชุดข้อมูลขนาดเล็ก (100 รายการ / ~300 ธุรกรรม): ลดขนาดลง **85.3%** (จาก 80.3 KB เหลือ 11.8 KB)
   - ชุดข้อมูลขนาดกลาง (1,000 รายการ / ~3,500 ธุรกรรม): ลดขนาดลง **98.5%** (จาก 808.4 KB เหลือ 11.8 KB)
   - ชุดข้อมูลขนาดใหญ่ (5,000 รายการ / ~17,500 ธุรกรรม): ลดขนาดลง **99.7%** (จาก 4.09 MB เหลือ 11.8 KB)
2. **ความเร็วในการประมวลผลและการตอบสนอง (Latency & Speedup Factor):**
   - มัธยฐานความเร็ว (Median Latency) ของการดึงประวัติเคลื่อนไหวเร็วขึ้น **1.48x ถึง 2.63x**
   - ความเร็วประมวลผลการกรอง 8 มิติ (8-Dimension Structured Filter) บน 5,000 รายการ ใช้เวลามัธยฐานเพียง **0.081 ms** (p95: 0.156 ms)
3. **ประสิทธิภาพของหน้าแรกและ MiniUI (Bootstrap & First Usable View):**
   - เมกะไบต์การโหลดเริ่มต้น (Bootstrap Payload): **811 ไบต์** (โหลดเฉพาะ session, user config, active FY)
   - ขนาดข้อมูล MiniUI สำหรับครูสแกน QR: **4,460 ไบต์** รองรับการเชื่อมต่อผ่าน 3G/4G ในพื้นที่ชนบทได้อย่างรวดเร็ว

## 3. การวิเคราะห์กลไกการปรับปรุงประสิทธิภาพ (Optimization Deep-Dive)

### 3.1 การแบ่งขอบเขตและจำกัดขนาดประวัติธุรกรรม (O-2: History Pagination & Slicing)
- **ปัญหาเดิม:** ฟังก์ชัน `getHistoryMap` ในอดีตส่งคืนแถวในชีต `stock_transactions` ทั้งหมดกลับไปยัง Frontend ส่งผลให้เมื่อมีการใช้งานนานปี ขนาด Payload พุ่งสูงเกิน 4 MB ทำให้เบราว์เซอร์กระตุกและติดโควตาการส่งข้อมูลของ Google Apps Script (50 MB/วัน)
- **การแก้ไข:** ปรับปรุง `getHistoryMap(fiscalYear, options)` ให้รองรับพารามิเตอร์ `limit` (ค่าเริ่มต้นสำหรับ Dashboard คือ 20 รายการล่าสุด) ขณะที่การคำนวณกราฟสรุปยอดประจำเดือน (Monthly Trends) ทำการ Aggregate ยอดรวมในหน่วยความจำโดยไม่ต้องเก็บ Object รายแถวที่ไม่จำเป็นไว้ในผลลัพธ์
- **ผลลัพธ์:** ขนาดข้อมูลคงที่อยู่ที่ ~11.8 KB แม้ฐานข้อมูลจะมีจำนวนธุรกรรมสะสมมากกว่า 17,000 แถว

### 3.2 กุญแจแคชจำแนกขอบเขตและเวอร์ชันข้อมูล (N-1: Scoped Cache Keys & Data Revision Token)
- **ปัญหาเดิม:** การแคชข้อมูลใช้คีย์ตายตัว เช่น `dashboard_kpis_2569` ทำให้เมื่อมีผู้ใช้บันทึกธุรกรรมใหม่ ผู้ใช้อื่นยังคงเห็นข้อมูลเก่าจนกว่าแคชจะหมดอายุ (TTL 120s) หรือหากมีการสลับระหว่าง Staging และ Production แคชอาจชนกัน
- **การแก้ไข:**
  - สร้างฟังก์ชัน `getCacheScopePrefix()`: `hrt_{env}_v{ver}_db{dbId}_`
  - เชื่อมโยง Data Revision Token (`data_revision`): เพิ่มค่าขึ้น 1 เสมอเมื่อมีการเขียนสต็อกหรือนำเข้าข้อมูล
  - กุญแจแคชสมบูรณ์: `hrt_gas_v2.7.0-rc.1_dblocal_dash_2569_rev3_d_วิทยาศาสตร์`
- **ผลลัพธ์:** ป้องกันการปนเปื้อนข้อมูลข้ามฐานข้อมูล และล้างแคช Dashboard ทันทีที่มีการเปลี่ยนแปลงสต็อกจริงโดยไม่ต้องรอหมดเวลา

### 3.3 การจัดทำดัชนีในหน่วยความจำ (O-3: In-Memory Indexing & Order-Invariant Line IDs)
- **การแก้ไข:** 
  - การจับคู่รหัสพัสดุกับ FSN ใช้วิธีสร้าง Hash Map `fsnMap[code]` ครั้งเดียวในแต่ละคำขอ ($O(1)$ lookup)
  - การสร้างรหัสแถวใบเบิกพัสดุ (Requisition Items) ใช้ฟอร์แมต `RQI-${reqId}-${it.item_code}` ซึ่งคงทนต่อลำดับของรายการ (Order-Invariant) และป้องกันความสับสนกรณีคำขอย้อนกลับหรือทำซ้ำ

## 4. ข้อจำกัดและข้อแนะนำสำหรับสภาพแวดล้อมจริง (Production Recommendations)

1. **โควตา Google Apps Script Execution Time:**
   - โควตาจำกัดเวลาของ Google Apps Script คือ 6 นาทีต่อการรันฟังก์ชัน
   - การประมวลผลคำขอปกติ (ดึงพัสดุ, ส่งใบเบิก, แสดงแดชบอร์ด) ใช้เวลาเฉลี่ยต่ำกว่า 500 ms จึงมีความปลอดภัยสูงมาก
2. **การนำเข้าข้อมูลขนาดใหญ่ (Batch CSV Import):**
   - แนะนำให้แบ่งไฟล์นำเข้าไม่เกิน 1,000 รายการต่อไฟล์ เพื่อให้อยู่ในกรอบเวลาประมวลผลและการจัดสรรหน่วยความจำที่ปลอดภัย
3. **การตรวจสอบสิทธิ์เชื่อมต่อ Google Workspace:**
   - ในการใช้งานจริงผ่าน `@hrt.ac.th` ผลการวัดความเร็วจะขึ้นอยู่กับเครือข่ายอินเทอร์เน็ตของโรงเรียนและเซิร์ฟเวอร์ Google Cloud Region ที่ให้บริการ
